# 1016 강의

강의 자료와 실습 내용을 정리하는 저장소입니다.

## 공유 재고관리

- 로컬 실행: `python -m http.server 8000 --bind 127.0.0.1` 실행 후 `http://127.0.0.1:8000/inventory.html`에 접속합니다.
- Vercel 배포: 프로젝트 루트의 `vercel.json`이 `/`를 `/inventory.html`로 연결합니다. Framework Preset은 **Other**, 별도 빌드 명령은 없으며 앱 파일이 있는 저장소 루트를 배포합니다.
- 등록된 이메일 계정으로 로그인한 사용자끼리 재고를 공유합니다. 기초재고·입고관리·출고관리 박스를 누르면 각각 입력 팝업이 열립니다.
- 품목 목록과 Excel 다운로드는 첨부 양식의 19개 필드를 사용합니다. 품번 클릭 시 입고별 잔량, 출고 내역의 금액 클릭 시 FIFO 차감 내역을 확인할 수 있습니다.
- 품목정보 등록 창에서 `Excel 업로드`를 누르면 운영체제의 `.xlsx` 파일 선택 창이 바로 열립니다. 파일을 선택해 열면 별도 업로드 확인 창 없이 품목을 일괄 등록합니다. 첫 번째 시트의 첫 행에 품목자산분류·재고자산종류·품번·품명·규격·재질·색상·단위·적정재고 열을 넣고, 열 순서와 제목의 공백은 자유롭게 지정할 수 있습니다. 등록 분류·단위와 중복 품번 등 모든 행을 검증하며, 오류가 하나라도 있으면 전체 등록을 시작하지 않습니다. 파일 선택 창의 크기는 브라우저 보안상 앱에서 제어할 수 없습니다.
- 입고등록 창에서도 `.xlsx` 파일로 입고 내역을 일괄 등록할 수 있습니다. 첫 번째 시트 첫 행에 품목분류·품번·품명·규격·색상·저장위치·납품업체·입고일자·입고수량·입고단가 열이 모두 있어야 합니다. 품번과 품목분류·품명·규격·색상이 등록된 품목정보와 일치하는지 확인하고, 미등록 품목은 별도 창에 표시하며 파일 전체 등록을 중단합니다.
- 재고 현황 메뉴는 재고 조회 → 입고 현황 → 출고 내역 → 품목 목록 순서입니다. 입고·출고 내역은 각각 해당 거래만 조회하며, 검색 초기화·인쇄·Excel 다운로드에도 거래 구분을 유지합니다.
- 검색용 날짜 입력칸은 1.3배 크기로 구성한 달력을 표시합니다. 날짜 칸 클릭 또는 `Alt+↓`로 열고, 연도·월 이동, 날짜 선택, 오늘 선택, 지우기를 사용할 수 있습니다. 날짜 직접 입력도 지원합니다.
- 각 팝업은 오른쪽 아래 모서리를 드래그해 가로·세로 크기를 조절할 수 있습니다. 입력·조회 팝업은 줄인 크기에 맞춰 본문을 스크롤하며, 인쇄에는 조절한 창 크기를 적용하지 않습니다.
- 출고는 기초·입고일자가 빠른 순서, 같은 날짜라면 등록 순서로 처리합니다. 수량 부족 시 전체 취소하며, 같은 품목의 동시 입출고는 DB 잠금으로 보호합니다.
- 최초 적용 시 기존 `supabase/schema.sql` 이후 **`supabase/fifo.sql`**을 실행하세요. 기존 단순 재고와 첨부 예시 데이터는 새 원장에 자동 등록하지 않습니다. 자세한 입력·원가 규칙은 [FIFO.md](FIFO.md)를 참고하세요.
- 품목자산분류를 사용할 때는 `supabase/fifo.sql` 적용 후 **`supabase/item-asset-classification.sql`**을 실행하세요. 화면 기본 분류는 첨부된 화면 이미지에 보이는 20개 항목이며, 추가 분류와 재고자산종류, 수량·금액 관리, 부족 통제, 세트품목, Lot관리 기본값을 설정할 수 있습니다. 수량 또는 금액 관리 안함으로 분류된 품목은 기초재고·일반 입출고·재고수불부·FIFO에서 제외되며, 발주 입고는 별도 이력으로 저장됩니다. 두 관리 옵션이 모두 켜진 품목만 재고수불부와 FIFO를 사용합니다. 재고자산종류가 미설정된 분류도 품목정보 등록에서 선택할 수 있지만, 품목 저장 전에 분류 설정에서 재고자산종류를 지정해야 합니다. 거래 이력이 있어도 재고금액관리 안함 설정은 변경할 수 있고, 과거 거래의 단가·금액은 자동으로 수정하지 않습니다. 재고수량관리 안함 설정은 이력이 있으면 변경할 수 없습니다.
- 기존 DB에 분류 설정 변경 제한을 갱신하려면 **`supabase/classification-value-management-edit.sql`**을 `supabase/item-asset-classification.sql` 이후 실행하세요.
- 품목정보·수주·입출고 입력 기록에 수정 버튼을 사용하려면 위 두 SQL 적용 후 **`supabase/edit-records.sql`**을 실행하세요. 수주는 입력 목록과 수주현황에서, 기초재고·입고·출고는 각 입력창의 저장된 내역 목록에서 수정할 수 있습니다. 거래 내역을 수정하면 해당 품목의 FIFO 원장을 다시 계산하며, 재고 부족이나 수주 출고수량 초과가 생기는 변경은 전체 취소됩니다. 출고가 연결된 수주의 품명·규격·단위와 출고수량은 일관성을 위해 제한될 수 있습니다. 품목자산분류와 관리자 계정은 기존 목록의 수정 기능을 사용합니다.
- 품목정보를 수정할 때 품목정보 현황에서 `수정`을 누르고 확인해야 등록 창이 열립니다. 이미 입력된 값은 변경할 수 없고 비어 있는 규격·재질·색상 등의 항목만 한 번 추가할 수 있습니다. 품번·규격 중복은 화면과 DB에서 차단합니다. 등록자명 표시와 DB 제한을 적용하려면 `supabase/edit-records.sql` 이후 **`supabase/product-info-controls.sql`**을 실행하세요. 기존 품목은 과거 등록자 기록이 없어 `기존 등록자`로 표시됩니다. 기존 규격 데이터가 서로 중복되면 해당 SQL 적용 전에 품목정보를 정리해야 합니다.
- 사용자 정의 입력 항목 기능은 화면에서 제거되었습니다. 기존에 `supabase/user-custom-fields.sql`을 적용해 저장한 데이터베이스 테이블과 값은 보존되며, 해당 SQL을 새로 실행할 필요는 없습니다.
- 발주 기능을 사용하려면 `supabase/fifo.sql`, `supabase/item-asset-classification.sql`, `supabase/classification-value-management-edit.sql`, `supabase/procurement-schema.sql` 적용 후 **`supabase/classification-procurement-workflow.sql`**을 실행하세요. 번호 자동 생성과 과거 발주일 제한을 기존 DB에 적용할 때도 이 workflow SQL을 다시 실행하세요. 발주번호는 발주일별 `ISPOYYYYMMDD-0001` 형식으로 자동 채번되며, 저장 함수에서 동시 등록을 잠금 처리하고 오늘 이전 날짜의 발주를 거부합니다. 재고관리 메뉴의 `발주관리`에서 구매발주 품목을 입력·조회하고 부분 입고할 수 있습니다. 발주 품목은 품목정보 등록에 등록된 품목 중에서 선택하며, 납품업체는 거래처 등록 업체 중에서 선택합니다. 품목별 납기예정일은 각 발주 품목에 지정하며 발주 품목표와 저장된 발주 현황에 표시됩니다. 관리 옵션이 모두 켜진 품목은 입고 시 FIFO/재고수불부에 반영하며, 수량 또는 금액 관리 안함 품목은 발주 입고 이력만 별도로 보존합니다. 기존 환경에서 분류 선택 오류를 방지하려면 재고자산종류가 없는 분류부터 분류 설정에서 종류를 지정하세요.
- 거래처 등록·조회 기능을 사용하려면 `supabase/schema.sql` 적용 후 **`supabase/vendor-management.sql`**을 실행하세요. 기본정보 → 거래처정보 입력 → 거래처 등록에서 거래처를 등록·수정·복사·삭제할 수 있고, 거래처 현황에서 검색·조회할 수 있습니다. 거래처 종류·분류·거래처명 생략명·지불계정 옵션도 등록 화면의 설정 메뉴에서 관리합니다. 기존 데이터베이스에 기능을 추가하는 경우에도 이 SQL을 실행하면 됩니다.
- 구매발주 입력의 납품업체는 거래처 등록에서 저장한 업체만 선택할 수 있습니다. 거래처 선택 목록을 사용하려면 `supabase/vendor-management.sql`을 적용하고 거래처를 먼저 등록하세요.
- 수주 입력에서 한 수주번호에 여러 품목을 등록하고 거래처명·연락처를 직접 입력하려면 FIFO·수주 수정·거래처 SQL 적용 후 **`supabase/sales-order-vendor.sql`**과 **`supabase/sales-order-groups.sql`**을 차례로 실행하세요. 다품목 SQL은 기존 수주 행을 각각 하나의 수주 그룹으로 보존하고, 품목별 출고 연결은 기존과 같이 유지합니다. 수주 품목을 수정하거나 삭제할 때 이미 출고된 품목의 출고 일관성을 보호합니다. 거래처 등록 여부와 관계없이 개인 또는 업체명을 입력할 수 있습니다.
- 매출관리에서 수주 현황 다음에 매출등록과 매출현황 조회를 사용할 수 있습니다. 두 메뉴에서 전체 수주 현황을 열고 수주번호 또는 거래처(성명)로 검색할 수 있으며, 검색 결과는 기존 수주현황과 동일한 목록으로 표시됩니다.
- 수주 상태를 진행·완료·중단으로 관리하고 매출등록의 품목별 완료 체크로 처리하려면 **`supabase/sales-status-workflow.sql`**을 수주 다품목 SQL 이후 실행하세요. 이 SQL은 기존 매출완료·매출미완료 값을 새 상태로 변환합니다. 일부 출고된 품목은 전체 수량이 출고되어야 완료할 수 있고, 중단 수주는 출고할 수 없습니다. 진행 수주만 출고 등록에서 선택할 수 있으며, 전량 출고된 수주는 자동으로 완료 처리됩니다.
- 출고 등록에서 진행 중인 수주번호를 선택하면 일치하는 등록 품목과 미출고 잔여 수량이 자동 입력됩니다. 수주 품목이 완료되면 선택 목록에서 제외됩니다. 수주 연결은 선택 사항이며, 수주와 연결할 때는 품목정보의 품명·규격·단위가 수주 품목과 일치해야 합니다.
- `/admin.html`에서 관리자 계정으로 로그인하면 사용자 생성, 이메일 및 비밀번호 변경, 사용 중지·재활성화가 가능합니다.
- DB 권한과 Vercel 서버 환경변수 설정은 [SUPABASE.md](SUPABASE.md)를 참고하세요.
